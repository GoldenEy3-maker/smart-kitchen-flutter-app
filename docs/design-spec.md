# ТЗ на дизайн мобильного приложения «Умная кухня»

Документ предназначен для дизайнера. Описывает структуру приложения, пользовательские сценарии, поэкранные требования и требования к дизайн-системе. На основе этого ТЗ отрисовываются макеты всех экранов приложения.

Черновые макеты ключевых экранов по этому ТЗ: `design/smart-kitchen.pen` (открывается редактором Pencil).

---

## 1. Общие сведения

| Параметр | Значение |
|---|---|
| Название | Умная кухня |
| Платформы | iOS, Android (Flutter) |
| Ориентация | Только портретная |
| Данные | Полностью локальные (Hive), без авторизации, без сети |
| Пользователи | Один пользователь, без профилей и настроек аккаунта |
| Язык интерфейса | Русский |
| Тема | Светлая (тёмная тема — этап 2, в макетах не требуется) |

**Суть приложения.** Пользователь ведёт учёт продуктов в холодильнике, хранит свои рецепты, составляет меню на неделю из этих рецептов с учётом того, какие ингредиенты уже есть в холодильнике, и формирует список покупок из недостающего.

**Ключевая ценность.** Приложение всегда «знает», что есть в холодильнике, и помогает ответить на два вопроса: «что я могу приготовить прямо сейчас?» и «что нужно докупить, чтобы приготовить запланированное меню?».

## 2. Структура приложения и навигация

Нижняя навигационная панель (таб-бар) из 4 вкладок:

| # | Вкладка | Назначение |
|---|---|---|
| 1 | Холодильник | Учёт продуктов: что есть, сколько, до какого срока |
| 2 | Рецепты | Каталог собственных рецептов |
| 3 | Меню | Меню на неделю: 7 дней × приёмы пищи |
| 4 | Покупки | Список покупок с чек-листом |

Стартовый экран — «Холодильник».

### Карта экранов

```
Таб-бар
├── 1. Холодильник (остатки продуктов)
│   ├── 1.1. Добавить в холодильник (выбор из каталога + количество + срок)
│   └── 1.2. Каталог продуктов (общий справочник)
│       └── 1.2.1. Новый продукт в каталоге
├── 2. Рецепты (список)
│   ├── 2.1. Детальный экран рецепта
│   └── 2.2. Создание / редактирование рецепта
├── 3. Меню на неделю
│   └── 3.1. Выбор рецепта в слот (модальный экран)
└── 4. Список покупок
    └── 4.1. Добавление позиции (модальное окно / bottom sheet)
```

Экраны 1.1, 1.2, 1.2.1, 2.2, 3.1 и 4.1 открываются поверх таб-бара (полноэкранно или как bottom sheet — на усмотрение дизайнера, но единообразно).

**Каталог продуктов** — общий справочник (`ProductCatalogItem`), не вкладка таб-бара. Доступ: кнопка «Каталог» на экране холодильника, при добавлении в холодильник, при выборе ингредиента в рецепте.

## 3. Пользовательские сценарии (ключевые flow)

### 3.1. Добавить продукт в холодильник
1. Вкладка «Холодильник» → кнопка «В холодильник» (или пустое состояние → «В холодильник»).
2. Экран «Добавить в холодильник»: **шаг 1** — выбор продукта из каталога (поиск + выбранная карточка) или «Создать новый продукт в каталоге»; **шаг 2** — количество и срок годности (опционально).
3. Сохранение → остаток появляется в холодильнике. Продукт уже существует в каталоге (или был только что создан).

### 3.1a. Управление каталогом продуктов
1. С экрана «Холодильник» → кнопка «Каталог» в шапке.
2. Просмотр всех продуктов справочника: поиск, фильтр по категории, список (название + ед. изм. по умолчанию).
3. «+ Новый продукт» → форма «Новый продукт в каталоге» (название, категория, ед. изм. по умолчанию — без количества и срока).
4. Тап по продукту в каталоге → редактирование записи каталога или «Добавить в холодильник».

### 3.2. Добавить рецепт
1. Вкладка «Рецепты» → кнопка «Добавить рецепт».
2. Заполнение: название, фото (опционально), время приготовления, порции, список ингредиентов (название + количество + ед. изм.), шаги приготовления (нумерованный список).
3. Сохранение → рецепт появляется в каталоге. На карточке сразу виден индикатор: хватает ли ингредиентов в холодильнике.

### 3.3. Составить меню на неделю
1. Вкладка «Меню» → выбор дня недели → выбор слота (завтрак / обед / ужин).
2. Открывается выбор рецепта: список рецептов, отсортированный «сначала те, на которые хватает ингредиентов». У каждого рецепта — индикатор наличия ингредиентов.
3. Выбор рецепта → слот заполняется карточкой рецепта.
4. Слот можно очистить или заменить рецепт.

### 3.4. Сформировать список покупок
1. На экране «Меню» — кнопка «Сформировать список покупок».
2. Приложение собирает все недостающие ингредиенты по рецептам недели (с учётом остатков в холодильнике) и добавляет их в список покупок.
3. Пользователь также может добавлять позиции в список покупок вручную.

### 3.5. Купил продукты → пополнить холодильник
1. Вкладка «Покупки»: пользователь отмечает купленные позиции чекбоксами.
2. Кнопка «Перенести в холодильник» — отмеченные позиции переносятся в холодильник (с возможностью уточнить срок годности), из списка покупок удаляются.

### 3.6. Контроль сроков годности
- В списке продуктов у каждого продукта с указанным сроком — цветовой бейдж: «свежий» / «истекает скоро (≤ 3 дней)» / «просрочен».
- Продукты с истекающим сроком визуально выделяются, чтобы их использовали в первую очередь.

## 4. Поэкранное описание

Для каждого экрана обязательно отрисовать заполненное состояние; для списков — также пустое состояние (иллюстрация + текст + призыв к действию).

### 4.1. Экран «Холодильник» (список продуктов)

**Назначение:** быстрый обзор всех продуктов, их количества и сроков годности.

**Элементы:**
- Заголовок экрана + счётчик продуктов (например, «Холодильник · 24 продукта»).
- Поле поиска по названию.
- Горизонтальная лента чипов-фильтров по категориям: Все, Овощи, Фрукты, Мясо и рыба, Молочное, Бакалея, Напитки, Соусы, Другое. Каждая категория имеет свою иконку/эмодзи.
- Блок-предупреждение (если есть): «N продуктов скоро испортятся» — акцентная плашка сверху списка.
- Список продуктов, сгруппированный по категориям. Карточка продукта:
  - иконка/эмодзи категории;
  - название;
  - количество + единица измерения (например, «2 шт», «500 г», «1 л»);
  - бейдж срока годности: зелёный «до 12 июля», жёлтый «истекает через 2 дня», красный «просрочен»; если срок не указан — бейдж отсутствует;
- Свайп по карточке (или меню): изменить остаток / убрать из холодильника.
- Кнопка «Каталог» в шапке — переход к общему справочнику продуктов.
- Плавающая кнопка «+ В холодильник» — добавление остатка (выбор из каталога).

**Состояния:**
- Пустое: иллюстрация пустого холодильника, текст «В холодильнике пока пусто», кнопка «В холодильник».
- Заполненное.
- Пустой результат поиска/фильтра.

### 4.2. Экран «Каталог продуктов»

**Назначение:** общий справочник всех продуктов приложения. Используется холодильником, рецептами и покупками.

**Элементы:**
- Навигация: назад, заголовок «Каталог продуктов», кнопка «+» (новый продукт).
- Подзаголовок: счётчик + пояснение («48 продуктов · общий справочник для холодильника и рецептов»).
- Поиск, фильтр по категориям (чипы).
- Список продуктов каталога, сгруппированный по категориям. Карточка:
  - эмодзи категории;
  - название;
  - единица измерения по умолчанию;
  - chevron (переход к редактированию или действиям).
- FAB «+ Новый продукт».

**Состояния:** заполненный, пустой каталог (редко — при первом запуске), пустой результат поиска.

### 4.2a. Экран «Новый продукт в каталоге»

**Назначение:** создание или редактирование записи в каталоге (без привязки к остатку в холодильнике).

**Поля:**
- Пояснение: «Продукт попадёт в общий каталог. Количество и срок годности указываются при добавлении в холодильник».
- Название (обязательное).
- Категория (чипы с иконками, обязательное).
- Единица измерения по умолчанию (шт / г / кг / мл / л / уп).
- Кнопка «Сохранить в каталог».
- В режиме редактирования — «Удалить из каталога» (деструктивная, с предупреждением если продукт используется в рецептах).

### 4.2b. Экран «Добавить в холодильник»

**Назначение:** добавление или пополнение остатка продукта в холодильнике.

**Элементы:**
- **Шаг 1 — выбор из каталога:**
  - поиск «Найти в каталоге…»;
  - выбранная карточка продукта (эмодзи, название, категория, ед. изм., chevron для смены);
  - ссылка «Создать новый продукт в каталоге».
- **Шаг 2 — остаток:**
  - количество (степпер, единица из каталога);
  - срок годности (опционально).
- Кнопка «Добавить в холодильник».

**Состояния:** продукт выбран (заполненное), продукт не выбран (кнопка неактивна).

### 4.3. Экран «Рецепты» (список)

**Назначение:** каталог собственных рецептов с индикацией готовности к приготовлению.

**Элементы:**
- Заголовок + поиск по названию.
- Фильтр-переключатель: «Все» / «Можно приготовить» (хватает всех ингредиентов).
- Сетка или список карточек рецепта:
  - фото рецепта (или стильная заглушка с иконкой блюда);
  - название;
  - время приготовления («40 мин»);
  - количество порций;
  - индикатор наличия ингредиентов: «Все ингредиенты есть» (зелёный) / «Не хватает 3 ингредиентов» (оранжевый).
- Плавающая кнопка «+ Добавить рецепт».

**Состояния:** пустое (иллюстрация + «Добавьте свой первый рецепт»), заполненное, пустой результат поиска.

### 4.4. Экран «Рецепт» (детальный)

**Назначение:** просмотр рецепта, проверка наличия ингредиентов, приготовление по шагам.

**Элементы:**
- Крупное фото (или заглушка) в шапке; кнопки «назад» и «редактировать» поверх.
- Название, мета-строка: время приготовления, порции.
- Сводка по ингредиентам: «Есть 5 из 7 ингредиентов».
- Блок «Ингредиенты» — список строк: название + количество; у каждой строки отметка наличия в холодильнике: есть (зелёная галочка) / нет (серый/оранжевый маркер «купить»).
- Кнопка «Добавить недостающее в покупки» (если чего-то не хватает).
- Блок «Приготовление» — нумерованные шаги, каждый шаг — отдельная карточка/строка с номером.

### 4.5. Экран «Создание / редактирование рецепта»

**Назначение:** форма рецепта.

**Поля:**
- Фото (плейсхолдер с кнопкой добавления, опционально).
- Название (обязательное).
- Время приготовления (минуты), количество порций — числовые поля/степперы.
- **Список ингредиентов из общего каталога продуктов** — не свободный текст, а выбор из того же справочника, что используется в холодильнике и списке покупок. Каждая строка:
  - **Выбор продукта** — picker/поиск по каталогу: иконка категории, название, категория, chevron для смены;
  - **Количество для рецепта** — степпер (сколько нужно для блюда), единица измерения берётся из каталога;
  - **Статус в холодильнике** — бейдж «В холодильнике» / «Нет в холодильнике» (информативный, только для подсказки при составлении рецепта);
  - кнопка «Убрать» строку.
- При добавлении ингредиента — поле поиска «Найти продукт в каталоге…» с выпадающим списком подсказок из каталога; если продукта нет — действие «Создать „…" в каталоге» (открывает форму добавления продукта в каталог, без привязки к остатку в холодильнике).
- Под заголовком секции — пояснение: «Ингредиенты выбираются из общего каталога продуктов — того же, что и в холодильнике».
- Шаги приготовления: динамический нумерованный список текстовых полей, «+ Добавить шаг», удаление шага.
- Кнопка «Сохранить».
- В режиме редактирования — кнопка «Удалить рецепт» (деструктивная).

### 4.6. Экран «Меню на неделю»

**Назначение:** планирование питания на 7 дней.

**Элементы:**
- Заголовок + переключатель недель (текущая / следующая; стрелки или свайп) с датами («7–13 июля»).
- Горизонтальный селектор дней недели (Пн–Вс) с датами; выделен выбранный день; «сегодня» помечен.
- Для выбранного дня — три слота: Завтрак, Обед, Ужин. Слот:
  - пустой: пунктирная карточка «+ Выбрать рецепт»;
  - заполненный: мини-карточка рецепта (фото-миниатюра, название, время приготовления, индикатор наличия ингредиентов) + меню «заменить / убрать».
- Внизу — сводная кнопка «Сформировать список покупок» с подписью, сколько ингредиентов не хватает на неделю (например, «Не хватает 8 ингредиентов»). Если хватает всего — состояние «Все ингредиенты есть», кнопка скрыта или неактивна.

**Состояния:** неделя пустая (все слоты пустые + подсказка), неделя частично заполнена.

### 4.7. Экран «Выбор рецепта в слот» (модальный)

**Назначение:** быстрый подбор рецепта в конкретный слот.

**Элементы:**
- Заголовок контекста: «Ужин · Среда, 9 июля».
- Поиск.
- Список рецептов, отсортированный: сначала «можно приготовить из имеющегося», затем остальные. Карточки — как в каталоге рецептов (компактный вариант), с индикатором наличия ингредиентов.
- Тап по рецепту — выбор и закрытие экрана.

### 4.8. Экран «Список покупок»

**Назначение:** чек-лист покупок.

**Элементы:**
- Заголовок + счётчик («Покупки · 8 позиций»).
- Список позиций: чекбокс, название, количество + ед. изм., пометка происхождения — «из меню» (автодобавленные) или без пометки (ручные).
- Отмеченные позиции зачёркиваются и опускаются в секцию «Куплено (N)».
- Кнопка «Перенести купленное в холодильник» (появляется, когда есть отмеченные) — переносит их в холодильник и убирает из списка.
- Кнопка «+ Добавить» — ручное добавление позиции (bottom sheet: название, количество, ед. изм.).
- Действие «Очистить список» (в меню экрана, с подтверждением).

**Состояния:** пустое (иллюстрация + «Список покупок пуст», подсказка «Сформируйте его из меню на неделю или добавьте вручную»), заполненное, частично отмеченное.

## 5. Модель данных (для понимания связей)

```
ProductCatalogItem (продукт в общем каталоге)
├── id
├── name: название (уникальное в каталоге)
├── category: категория (из фиксированного списка)
└── defaultUnit: шт | г | кг | мл | л | уп

FridgeItem (остаток в холодильнике)
├── catalogItemId → ProductCatalogItem
├── quantity: число
└── expiryDate: срок годности (опционально)

Recipe (рецепт)
├── name, photo?, cookingTimeMinutes, servings
├── ingredients: [RecipeIngredient]
│   ├── catalogItemId → ProductCatalogItem
│   └── quantity: сколько нужно для рецепта
└── steps: [текст шага]

WeekMenu (меню недели)
└── days[7] → slots {завтрак, обед, ужин} → recipeId?

ShoppingItem (позиция списка покупок)
├── catalogItemId → ProductCatalogItem (или name для обратной совместимости)
├── quantity, unit
├── isChecked: куплено или нет
└── source: из меню | вручную
```

**Ключевая связь:** все модули ссылаются на один **каталог продуктов** (`ProductCatalogItem`). Холодильник хранит остатки (`FridgeItem`), рецепты — требуемое количество (`RecipeIngredient.catalogItemId`), покупки — что нужно докупить. Наличие ингредиента определяется сравнением `RecipeIngredient.quantity` с суммой остатков `FridgeItem` для того же `catalogItemId`. Отсюда индикаторы «хватает / не хватает» на карточках рецептов, в слотах меню и генерация списка покупок.

## 6. Требования к дизайн-системе

### 6.1. Общая стилистика

- **Не** привязываться к Material 3 и стандартным компонентам — нужен собственный визуальный язык в стилистике современных food-приложений (референсы по духу: Yummly, Whisk, Mealime, «Едадил»).
- Настроение: тёплое, «аппетитное», дружелюбное, лёгкое. Приложение — домашний помощник, а не строгий инструмент.
- Мягкие крупные скругления карточек и кнопок, много «воздуха», мягкие ненавязчивые тени.
- Активное использование иконок/эмодзи для категорий продуктов и иллюстраций для пустых состояний — единый стиль иллюстраций на всех экранах.

### 6.2. Палитра (ориентир, финальные значения — за дизайнером)

- Основной акцент: тёплый зелёный (свежесть, продукты) — кнопки, активные табы, индикатор «всё есть».
- Вторичный акцент: тёплый оранжевый/терракотовый — акценты, «не хватает ингредиентов», предупреждения о сроках.
- Фон: тёплый светлый (кремовый/молочный), карточки — белые.
- Семантические цвета сроков годности: зелёный (свежий), жёлтый/оранжевый (истекает ≤ 3 дней), красный (просрочен).
- Текст: тёмный тёплый графит + серый вторичный.

### 6.3. Типографика

- Один шрифт с поддержкой кириллицы (например, из Google Fonts: Manrope, Rubik, Nunito — на усмотрение дизайнера).
- Шкала: крупный заголовок экрана, заголовок секции, основной текст, вторичный текст/подписи, текст бейджей.

### 6.4. Компоненты (нужны в макетах как единая библиотека)

- Таб-бар (4 вкладки, кастомный, с активным состоянием).
- Карточка продукта (с бейджем срока годности).
- Карточка рецепта (полная и компактная для слотов меню/выбора).
- Чипы категорий и фильтров (обычное и выбранное состояние).
- Бейдж срока годности (3 семантических состояния).
- Индикатор наличия ингредиентов (есть всё / не хватает N).
- Кнопки: основная, вторичная, деструктивная, плавающая «+».
- Поля формы: текстовое, числовое со степпером, селектор единиц, выбор даты, выбор категории.
- Чекбокс списка покупок (в фирменном стиле).
- Слот меню (пустой пунктирный и заполненный).
- Поисковая строка.
- Пустые состояния (иллюстрация + текст + кнопка).
- Bottom sheet.

### 6.5. Прочие требования

- Базовая сетка: горизонтальные поля экрана 16–20 px, единый вертикальный ритм.
- Целевой размер артборда: 390 × 844 (iPhone-класс), дизайн должен адекватно растягиваться на Android.
- Минимальная область касания 44 × 44 px.
- Все тексты в макетах — на русском, с реалистичным контентом (настоящие продукты и рецепты, не lorem ipsum).

## 7. Состав макетов (чек-лист для дизайнера)

1. Холодильник: заполненный, пустой.
2. Каталог продуктов: заполненный.
3. Новый продукт в каталоге.
4. Добавить в холодильник.
5. Рецепты: заполненный список, пустой.
6. Детальный экран рецепта (с недостающими ингредиентами).
7. Создание/редактирование рецепта (ингредиенты из каталога + поиск/создание).
8. Меню на неделю: частично заполненное, пустое.
9. Выбор рецепта в слот.
10. Список покупок: заполненный с отмеченными позициями, пустой.
11. Лист компонентов дизайн-системы (палитра, типографика, компоненты из п. 6.4).

## 8. Вне объёма (этап 2)

- Тёмная тема.
- Онбординг.
- Статистика и аналитика потребления.
- Синхронизация с облаком, шаринг рецептов и меню.
- Уведомления о сроках годности.
